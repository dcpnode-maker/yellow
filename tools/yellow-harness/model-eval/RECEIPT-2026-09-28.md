# First GPU coding-model smoke — 28 September 2026

The private synthetic Kaggle GPU notebook ran official
`Qwen/Qwen2.5-Coder-1.5B-Instruct` at fixed revision
`2e1fd397ee46e1388853d2af2c993145b0f1098a`. The first attempt loaded
weights but failed because tokenization output was passed as one positional
argument to `generate`. The local cell was repaired to call
`generate(**tokens, ...)`; local contract tests passed before the retry.

The retry took **3.74 s to load** and **10.69 s to generate** a response, with
**6,203,848,704 bytes** peak memory allocated on GPU 0. This is a one-prompt
smoke, not a representative throughput benchmark.

The generated `collapse_ranges` code **failed the requested contract**:

- It sorted `intervals` in place, mutating the caller's input.
- It did not reject a range whose end precedes its start.
- Its second asserted result merged `(1, 6)` and `(8, 9)`, which are not
  touching closed integer ranges.
- The response continued after the code block and was cut at the 240-token cap.

The output was not executed or applied to Yellow. This result rules out
selecting the 1.5B model as a Yellow coding worker on current evidence. It
does not prove that larger models will pass. The GPU session's shutdown could
not be verified after the original browser tab switched accounts, so Order
683's shutdown acceptance remains open.
