## Packet contract — every worker, every task

1. Coordinator selects the active order and lists exact input/output paths and
   source hashes. Inspect fresh files, not an old transcript. No order means no
   app edit. Preserve dirty/staged work and frozen471/paused445 exclusions.
2. Send only the relevant specification and files, not the whole conversation,
   database, credentials, client data or unrelated project context.
3. Worker returns a patch/proposal in protected private state. It receives no
   database credential, migration, push, merge, deployment or billing authority.
4. Coordinator inspects the diff, applies within scope, runs exact focused tests
   and records results. Skips are not passes. High-risk proof remains personally
   executed by an independent non-implementer. No whole-project review loop for
   every small task, and no unchanged retry presented as a repair.
5. Save task ID, model, base/source hashes, proposed/accepted output hashes,
   commands, actual results, failures and next dependency. Preserve failed
   generations. Checkpoint after each accepted packet; do not copy worktrees.

Start with two cloud proposal workers maximum. Reduce concurrency if free RAM
falls below4GiB or tests contend. Never run a local model alongside both heavy
CLI workers on this16GiB laptop. Qwen is on-demand and unloads; no WSL/Docker.
Do not disable Defender, memory compression, essential Windows services, the
active Codex process or database services to make a larger model fit.

On401/403 stop that route for authentication; on429 wait for the published reset
or dispatch to a separately authorized, available provider. No retry storms or
quota circumvention. An invalid patch gets one precise repair packet; recurring
same failure escalates to the coordinator rather than burning repeated tokens.
