The Dockerfile has no `RUN`, source copy, package install, build, or migration instruction. Build is explicitly `--network=none --pull=false`; the candidate must retain all 11 exact b9 rootfs diff IDs, user, command, OS/architecture, and carry the exact 444 revision label and build SHA. Thus the method is a config-only identity repackage of already verified b9 product bytes, not an independently compiled 444 source image. Any rootfs diff-ID change is a hard failure.

The runner saves the candidate image to a fresh private Docker archive, invokes the pinned public b9 Docker-save-to-OCI converter with candidate config digest and expected ordered diff IDs, then runs the new independent `verify_candidate_oci.py`. The verifier checks OCI layout/index/manifest/config descriptors, opaque config digest against the immutable candidate image ID, every compressed layer digest and byte count, every decompressed diff ID in order, and rejects extra/missing files, oversized metadata, symlinks, or altered layers. It never decodes `Config.Env`. The proof records the config-only method, exact rootfs identity and candidate metadata separately; no registry digest or cold-cache claim is made. The candidate image is not started by the image/export script.

The image builder is a single 300-second attempt with a 30-second final checkpoint reserve, no automatic retry, Docker CLI pinned to `unix:///var/run/docker.sock`, and Docker endpoint/context/TLS selectors cleared while other environment is preserved. The only Docker mutation is the candidate image build/tag and archive export. It does not create/start containers, pull, prune, remove images, or change source/old-service state. Private output is fresh under `private-candidate-444-v1`; the public proof path must also be fresh. On any error the runner records only stage/error type privately and public stdout; it does not delete candidate images or broad resources.
