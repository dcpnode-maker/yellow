# Q708 — mounted toolbar reset correction

During Order708 browser proof, Reset retained the typed search and sort order.
The existing reset handler calls onTableChange with empty criteria, then calls
clearStayCriteria, which restores the old search/sorts from its closure. This is
a frontend-only inherited bug, not a hotel-state transition.

MovementTableControls.tsx was admitted only for field bindings. Product edits to
this handler paused here before widening that scope. Under D-91 routine technical
authority, root explicitly admits this exact reset correction and a focused
regression in Order708; no founder business-policy choice is needed. Reset should
clear search/filter/stay criteria and custom sorting, restoring default sorting
and initial visible columns.
Independent review and mounted reset proof are required before final release.

Portal integration also requires TableColumnMenu's document-level Escape capture
to defer when focus belongs to an open field-dictation panel. Without this exact
UI-only guard, Escape would close the containing column menu before the field can
cancel. Root explicitly admits the guard and regression under the same routine
authority; no query application or domain handler changes are admitted.
