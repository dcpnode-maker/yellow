## Gate 2 — Tier-3 challenge to Decision B: migration runner

OpenAI's challenge and recommendation:

1. Hold one **session-level** advisory lock across the complete pending set on one
   reserved Bun SQL connection. A per-file transaction lock releases between files
   and does not serialize the run; a pool does not guarantee connection affinity.
2. Keep one transaction per ordinary file, but explicitly reject nontransactional
   statements in Phase 0. `CREATE INDEX CONCURRENTLY` cannot run in a transaction and
   failed concurrent builds can leave invalid indexes. A nontransactional migration
   mode requires a later reviewed design.
3. Specify the migration/deployment identity. The baseline's `app_role` has no
   provisioned password and must not write migration history; local `yellow` is a
   development superuser. Do not imply that a production migration credential
   already exists.
4. Hash exact bytes with SHA-256 and fail closed on mismatches, duplicate versions,
   applied versions absent locally, and ambiguous ordering.
5. Add executable proofs for connection-affine locking, concurrent runners, process
   death releasing the session lock, checksum mutation, rollback, second-run no-op,
   and rejection of forbidden statements before success is recorded.

Please incorporate or reject each point, append the resulting Tier-3 decision to
`DECISIONS.log`, and only then write the migration-runner order.

## Gate 3 — Tier-3 challenge to Decision C: launch seed

OpenAI's challenge and recommendation:

1. Define how “runs as application role” works. A practical local/CI path is a
   deployment connection that starts one transaction, uses `SET LOCAL ROLE app_role`,
   and calls transaction-local `set_config` on that same connection. Production
   credentials remain externally provisioned.
2. Use exact-match idempotency: an identical repeat is a no-op, but an existing
   deterministic identifier with conflicting canonical values fails. Blind
   `ON CONFLICT DO NOTHING` can conceal configuration drift.
3. The immutable baseline does not install `uuid-ossp`; PostgreSQL 16 core does not
   provide UUIDv5. Compute UUIDv5 in TypeScript from an architect-fixed namespace and
   name with standard test vectors, or choose fixed approved constants. Do not edit
   migration 0001 to add an extension.
4. Keep the production launch seed to the required one tenant/property. Create a
   second tenant only in the test fixture used to prove isolation.
5. Prove transaction-local tenant context clears after commit and rollback and cannot
   leak when the pool reuses a connection.

Question 007's “idempotent no-op” and “minimum proof: two tenants” are compatible if
the launch seed and isolation fixture are treated as separate artifacts. Please make
that separation explicit in the decision and order.

## Gate 4 — Tier-3 challenge to Decision D: CI, RLS, and schema drift

OpenAI's challenge and recommendation:

   not prove the future production runner or launch seed. CI must invoke those paths.
2. Keep the Python battery as the sole domain-invariant oracle, but distinguish two
   contracts:
   - deployment acceptance: empty database → runner → launch seed → exact seed and
     health/catalog assertions;
