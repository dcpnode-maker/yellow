# Order 063 — Universal rate-plan product contract

**Phase:** 3 · Rates and policies  
**Branch:** `phase-3/universal-rate-plan-contract`  
**Tier:** 1 — documentation and order decomposition only  
**Written by:** OpenAI Codex, autonomous temporary architect under D-95/D-115/D-221

## Outcome

Turn the founder's universal-rate-flow direction into a durable requirement matrix and a
sequenced Phase 3 implementation plan. Hotels must be able to start from a simple preset,
select a known pricing model, or compose an expert model while Yellow continues to enforce
typed money, reproducible resolution, authorization, audit history and jurisdictional rules.

This order changes no runtime behavior. It prevents the screenshot and chat direction from
becoming an informal promise that later implementation only partially remembers.

## Required work

1. Record the five-step flow: create, price, target, schedule and review/publish.
2. Map every founder-named pricing model, applicability dimension, commercial dimension,
   advanced rule, conflict rule and bulk-edit behavior to a numbered future order.
3. Define guided and expert modes as two presentations over the same commands and stored
   meaning, never two pricing implementations.
4. Define hotel configurability and the non-configurable compliance/invariant envelope.
5. Make AI assistance a compiler into the same typed draft/preview commands. It may explain,
   simulate and reject impossible intent; it has no privileged write or publish path.
6. Separate planning decisions from persistence decisions. Each implementation order must run
   the Natural-Solution Test before authorizing a migration or new primitive.

## Forbidden

- Any runtime, migration, schema snapshot, package, test or workbench change
- Editing `migrations/0001_init.sql` or `tests/run_invariants.py`
- Choosing a storage design before the implementation order's schema preflight
- Arbitrary JavaScript/SQL/formula execution supplied by a hotel or AI model
- A second rate, quote, tax, restriction, audit, authorization or publishing path
- Making tax law, fiscal requirements, money precision, tenant isolation, audit history,
  occupancy truth or jurisdictional checks hotel-disableable
- Claiming the future implementation is already built or independently reviewed
- Approval or merge by Codex

prices, restrictions, market/source fields and progressive forms—but no complete contract for
model selection, applicability hierarchy, commercial targeting, deterministic conflict review,
bulk publish/versioned undo or AI intent compilation. The plan's matrix is the proof for this
documentation-only order; later orders must supply executable domain and UI proofs.
