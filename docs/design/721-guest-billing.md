# Guest billing721 — concept and implementation contract

Founder requested guest billing instead of cash drawers, smaller field microphones,
compact icons and the “3 UI flaws” reference (not glass). Concept generated with
built-in ImageGen, ui-mockup brief: full white professional ERP guest billing screen,
narrow guest/bill column, exact balances, four compact charge/split/direct-bill/
deposit actions above statement, explicit confirmation and checkout navigation.
Concept: `721-guest-billing-concept.png` (fictional Alex Morgan/125SAR).

White #fff; rail#f6f7f6; ink#20251f; border#d8ded4; pale selected#f1ffdc;
neon accent#b6ff00. Heading24px/21px; controls12–14px; outline16px1.7stroke;
mic14px with transparent44px touch target and32px fine-pointer desktop target.
One low-contrast horizontal action ribbon, optional action content, statement
table; no repeated large cards or financial analytics. Mobile folds to one column,
two balances remain side-by-side and four actions remain one44px-min tap row.

Allowed copy: existing guest/reservation/window identifiers and states; Cashier &
folios; Find guest or bill / Change reservation or find a bill; Post a charge;
Split bill; Direct billing; Deposits; Reservation / checkout; existing table
controls/labels and exact financial confirmations, errors and recovery explanations.

Intentional differences from generated concept: preserve actual Yellow shell and
font; do not adopt invented Grandview/nav/bell/profile controls. Use server data,
not fictional sample rows. Retain the real seven-column ledger including code and
quantity and original-order balance explanation. Existing configured-charge group
picker remains instead of inventing autocomplete/backend contract; amounts remain
clearly labeled minor units. Retain exact existing confirmation copy and explicit
financial messages. Add-window opens its existing reviewed form rather than a
decorative plus tile. Compare-windows appears only with multiple windows. Search
is a compact full-width disclosure, not an unimplemented header search.

Kole's resources page exposes Dashboard Flaws but the supplied video's three
points could not be verified; no specific advice is falsely attributed to it.
Official Oracle billing/charge docs informed reservation context, window separation
and keeping posting, settlement and checkout distinct. No cloned proprietary code.
